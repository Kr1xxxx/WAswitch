## WA-001：版本预分配导致增量同步漏更新

**触发与影响：** 两个请求交错提交时，先取得较小版本号的请求可能较晚提交。客户端先读到较大版本并推进 cursor，随后无法再读到较小版本的变更，可能漏掉账号收回指令。

**根因：** 全局版本号在业务事务外预分配，版本顺序不能反映实际提交顺序。

**修复：** [0003_atomic_seats.sql](../server/migrations/0003_atomic_seats.sql) 用数据库触发器在坐席插入或可见状态更新时递增并写入版本。版本更新与业务写入一起提交或回滚；[admin.js](../server/src/admin.js) 和 [device.js](../server/src/device.js) 不再提前申请版本。

**必须保留的约束：** 所有坐席变更都经触发器生成版本；不得恢复事务外预分配，也不得单独覆盖已有坐席版本。

**回归证据：** `check:review` 中的“提交顺序反转后，客户端仍能在后续增量中拿到收回指令”和“延迟的改名请求不会重新激活旧电脑；事务失败不会提前消耗版本”。

## WA-002：并发分配留下多个有效坐席

**触发与影响：** 两个请求同时把一个账号分配给不同电脑，或改名请求与分配请求交错执行，旧归属快照可能使多台电脑继续保留有效坐席。

**根因：** 撤销旧坐席和刷新账号信息依赖请求开始时读到的 device_id，数据库缺少单账号唯一有效坐席约束。

**修复：** 分配在同一批事务中隐藏所有旧有效坐席、更新账号归属、启用新坐席；改名按事务内的当前归属刷新版本。迁移清理历史不一致坐席并建立部分唯一索引。设备同步同时检查坐席、权威归属和删除状态。

**必须保留的约束：** 每个账号最多一个可见坐席；账号归属以 wa_accounts 为准；失去归属的电脑收到隐藏记录，不能凭旧坐席上报状态或启用 CRM。

**回归证据：** `check:review` 中的并发分配、延迟改名、历史重复坐席迁移三个用例；`check:team` 中的换人、收回和删除检查。

## WA-003：同代理网关串用账号凭据

**触发与影响：** 多账号共用同一代理 host/port、使用不同用户名或密码时，认证回调可能取到另一个账号的凭据，破坏代理线路隔离。

**根因：** 原逻辑只按网关地址和端口匹配，并取第一个账号。

**修复：** [main.js](../src/main.js) 的 login 回调先按 webContents.session 筛选账号，再由 [proxy.js](../src/proxy.js) 的 credentialsFor 选择唯一的一组凭据。没有页面归属的后台请求只在匹配凭据完全一致时允许；歧义或无法解密时取消认证。

**必须保留的约束：** 网关相同不等于账号相同；不能以“第一个匹配账号”兜底。后台请求因歧义被拒时，可使用各账号独立的本地代理端口。

**回归证据：** `check:review` 验证 A/B session 各取自己的凭据、未知 session 拒绝、无 session 且凭据有歧义时拒绝、相同凭据时允许。

## WA-004：页面时间被主进程时区错误解释

**触发与影响：** 账号页面时区与电脑系统时区不同，消息时间在主进程重新构造后会偏移，可能把旧消息当作 CRM 开关打开后的消息，或漏收新消息。

**根因：** 页面只返回年月日时分，由主进程使用系统时区解释。

**修复：** [wa-page.js](../src/wa-page.js) 在账号页面隔离环境中将时间转成毫秒时间戳；[crm/web.js](../src/crm/web.js) 直接使用该时间。日月有歧义时保留候选；不存在的日期、夏令时跳过的本地时间和无法选择的候选不伪造为当前时间。

**必须保留的约束：** 主进程不得再次用本地 Date 重建页面时间；不可靠时间进入跳过计数。日月歧义的选择仍是估计，必须保留 approx 标记。

**回归证据：** `check:review` 覆盖新加坡、纽约时间转换和夏令时缺失时刻；`check:team` 的 CRM 检查覆盖日期解析与日月歧义；`check:float` 检查页面读取结果。

## WA-005：滚动加载的无时间历史被误收

**触发与影响：** 已打开的聊天向上滚动后，历史消息第一次出现在 DOM 中；没有可识别时间的消息可能被当作刚收到的消息采集。

**根因：** 原逻辑把“本次运行中首次看到消息 ID”当作新消息证据，并用当前时间补齐缺失时间。

**修复：** [crm/web.js](../src/crm/web.js) 对没有可靠时间的消息统一跳过；已见 ID 集合仅用于避免重复累计跳过次数。

**必须保留的约束：** 首次出现、首次渲染、滚动加载都不能证明消息是新收到的；不能用 Date.now() 补消息时间。无法解析时间的新消息也会跳过，这是当前采集边界。

**回归证据：** `check:review` 中的“已读过的对话滚动出现无时间历史时不采集，也不反复累计跳过”；CRM 自检的无时间消息用例。

## WA-006：闲置 CRM 队列未按期清理

**触发与影响：** 停止收到新消息后，过期内容可能在队列和磁盘保留超过 7 天。

**根因：** 清理依赖新增或写入事件，缺少闲置期清理路径。

**修复：** [crm/queue.js](../src/crm/queue.js) 在加载、stats、peek 和 sweep 时清理，发生变化立即保存；主进程每 15 秒检查，恢复运行时也执行清理。

**必须保留的约束：** 不依赖新消息触发过期清理；清理内存后同步更新磁盘；上传读取不能返回已过期条目。程序关闭或电脑休眠期间无法主动清理，重新运行或恢复后执行。

**回归证据：** `check:review` 验证重启、读取、定时清理三个入口，并检查内存结果与磁盘内容；CRM 自检检查 7 天和容量上限。

## WA-007：锁屏时轻量账号仍自动已读

**触发与影响：** 应用锁定后窗口仍处于可见、聚焦状态，incoming 回调可能向对方发送已读回执。

**根因：** userIsReading 判断窗口和当前聊天，却未检查应用 locked 状态。

**修复：** [main.js](../src/main.js) 的 userIsReading 增加未锁定条件。

**必须保留的约束：** 自动已读同时要求未锁定、当前账号、当前聊天、窗口可见且聚焦等条件；不能仅凭页面还存在或窗口聚焦判断用户正在阅读。

**回归证据：** `check:review` 调用真实 incoming 事件处理器，验证锁定时不发已读，解锁后正常发送；轻量测试覆盖基础已读行为。

## WA-008：Linux basic_text 被当作安全加密

**触发与影响：** Linux 缺少安全钥匙环时，Electron 可能回退到 basic_text；敏感凭据被保存，但只得到混淆保护。

**根因：** 部分调用仅检查 isEncryptionAvailable，没有排除 basic_text，模块之间的检查规则不一致。

**修复：** [secure-storage.js](../src/secure-storage.js) 统一 canEncrypt，拒绝不可用后端、Linux basic_text 和检查异常；轻量密钥、代理密码、团队令牌、CRM 队列及翻译存储复用此检查。

**必须保留的约束：** 新增敏感数据存储时复用 canEncrypt，不自行退回仅检查 isEncryptionAvailable；保存失败不能改存明文；不能把凭据写入日志或问题记录。

**回归证据：** `check:review` 覆盖 basic_text、后端异常、正常钥匙环，并确认拒绝时没有加密写入或团队登记请求；CRM 与翻译检查覆盖各自存储行为。

## 修改相关代码前的检查

1. 找到对应问题编号，确认上述约束仍成立。新增写坐席、代理认证、采集或密钥存储入口时，也要覆盖新入口。
2. 先保留能复现原错误的测试，再修复业务代码；不要为了通过检查而删除失败断言或放宽边界。
3. 按影响范围运行下列命令，并查看 [CI 配置](../.github/workflows/ci.yml)。完整 CI 还包含图形界面、打包和启动检查。

```sh
npm ci
npm run check:review     # 本文件 8 项问题对应的 10 项回归
npm run check:team       # 团队、后台、CRM
npm run check:lite       # Electron 内置 Node 和系统 Node
npm run check:translate
npm run check:float      # 包含 Electron 页面测试，需要图形环境
```

4. 在修改的 PR 描述中引用问题编号，附相关测试结果；更新本文件状态和证据。图形界面手动验证参见 [验收清单](acceptance.md)。
5. 后台发布前核对迁移顺序：先应用 [0003_atomic_seats.sql](../server/migrations/0003_atomic_seats.sql)，再部署依赖它的 Worker。已有数据库只执行尚未应用的迁移，参见 [后台部署说明](../server/README.md)。
