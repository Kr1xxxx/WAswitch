# WAswitch

在一个窗口里同时登录多个 WhatsApp 账号的桌面软件（Windows / macOS / Linux）。

## 原理

基于 Electron。每个账号加载 `https://web.whatsapp.com`，并使用独立的 session 分区
（`persist:wa-<id>`），所以每个账号的 cookie、本地存储和登录状态完全隔离，关掉软件再打开也不用重新扫码。

为什么不做成纯网页：WhatsApp Web 禁止被 iframe 嵌入，而且同一个浏览器里的多个标签页共享同一份登录状态，
网页版无法真正“多开”。桌面应用没有这个限制。

## 安装

在 [Releases](https://github.com/Kr1xxxx/WAswitch/releases) 下载最新的安装包：Windows 用 `.exe`；macOS 用 `.dmg`（只支持 M 系列芯片）。

安装包没有做代码签名（需要付费证书），第一次打开时系统会拦一下：

- **Windows**：出现“Windows 已保护你的电脑”时，点“更多信息”，再点“仍要运行”。
- **macOS**：把 WAswitch 拖进“应用程序”后，第一次在“应用程序”里**右键点 WAswitch → 打开**，再点“打开”。如果提示“已损坏”，在终端运行 `xattr -cr /Applications/WAswitch.app` 后再打开。

只能同时运行一个 WAswitch，重复打开会直接显示已经开着的窗口。

开机自动启动：Windows 上会直接缩在托盘里；macOS 13 及以后系统不告诉软件是不是开机启动的，所以 Mac 上开机后会正常弹出窗口。

## 功能（当前版本）

- 左侧账号栏：显示名称、颜色、线路和未读数；左上角按钮可以收起成只显示图标
- 添加账号：起名、选颜色、设代理并测试，然后扫码登录
- 右键账号或点顶栏“⋯”：编辑、刷新、不弹通知、删除（清除这个号在本机的数据；手机的“已关联的设备”里需要手动退出）
- `Ctrl`（macOS 是 `Cmd`）+ `1` 到 `9`：切换到第几个账号
- 代理连不上时显示原因，并自动重试（10 秒起，最长每分钟一次）；电脑睡眠醒来后自动重连
- 设置页：内存、通知、通用（关闭窗口缩到托盘、开机自动启动、侧栏只显示图标）、隔离自检、关于
- 日志：每天一个文件，保留 7 天，只记录软件运行情况，不记录聊天内容和号码。设置 › 关于 › 打开日志文件夹
- 按账号区分的桌面通知：哪个号有新消息就显示哪个号的名字，点通知直接切到那个号；每个号可以单独静音
- 托盘图标和总未读数：任务栏/Dock 显示所有账号的未读总数；关闭窗口会缩到托盘，后台继续收消息，从托盘菜单退出
- 主号和小号：第一个网页版账号默认是主号，可以在编辑账号里换。小号可以选“轻量模式”（见下文）

## 轻量模式（小号，试验功能）

添加账号时可以选“轻量模式”：不打开 WhatsApp 网页，而是在一个共用的后台进程里直接连接 WhatsApp，每个号只占几十 MB 内存（网页版每个约 300 MB）。基于开源库 [Baileys](https://github.com/WhiskeySockets/Baileys)（固定版本 7.0.0-rc14）。

**风险：轻量模式不是官方客户端，WhatsApp 可能识别出来并封号，通常发生在几天到几周内。请先用一个不重要的号连续试用两周，再考虑用在正式号上。** 主号只能用网页版，软件里不允许把主号设成轻量模式。

能做的：扫码登录、看对话列表、收发文字、未读数和通知（和网页版一样只显示“有 N 个未读对话”）。
暂时不能做的：图片、语音、文件只显示“[图片]”这类说明，内容请在手机上看；不能发图片；不能给没有对话的号码发消息。

安全和隔离：

- 必须设置代理（socks5 或 http），并且测试通过才能保存；不能直连。出口 IP 不能和主号相同，和其他号相同时会提醒。
- socks5 代理一律让代理解析域名，本机不查询任何 WhatsApp 域名。
- 后台进程装了网络护栏：除了代理本身，任何连接、DNS 查询和 UDP 都会被拦下，所以即使某个功能漏了代理，也只会失败，不会暴露真实 IP。拦下的次数显示在隔离自检里。
- 不联网查询协议版本号（用 Baileys 内置的版本），不主动显示“在线”；只有点开对话时才发蓝色已读。
- 每个号每分钟最多发 10 条。
- 登录凭据和聊天缓存用 AES-256-GCM 加密后保存在本机；密钥用系统钥匙串加密。聊天缓存每个对话最多保留 500 条文字。
- 数据密钥绑定这台电脑的这个系统用户（系统钥匙串）。把数据文件夹复制到别的电脑、或换了系统用户后读不出来，只能删掉这个号重新添加、重新扫码。
- 手机上移除了设备，或 WhatsApp 拒绝连接（可能被封）时，停止自动重连，侧栏变红并弹通知。
- 删除轻量账号时会让手机“已关联的设备”里的这台设备一起退出。
- 聊天里的链接只允许 http、https、mailto、tel，用系统程序打开。

离线自检（不需要联网和账号，用本机假代理验证上面几条）：

```bash
npm run check:lite
```

## 账号隔离

每个账号在三个层面上彼此独立：

| 层面 | 做法 |
| --- | --- |
| 数据 | 独立的 cookie、登录状态、本地存储和缓存 |
| 网络 | 每个账号可以单独设置代理（socks5 / http）。代理连不上时这个账号断网，不会改用直连；WebRTC 也被限制为只走代理，不会泄露真实 IP |
| 环境 | 每个账号的浏览器标识、语言、时区按它的地区单独设置，时区和语言与代理出口一致 |

用 Clash 给每个账号分配不同节点的方法，见 [docs/clash.md](docs/clash.md)。

带密码的代理，密码用系统钥匙串加密后保存在本机。

通知说明：通知根据每个账号页面标题里的未读数生成，只显示“账号名：有 N 个未读对话”，不读取聊天内容。这个数字是“有未读消息的对话数”，所以同一个对话里连续来的新消息不会再弹通知，直到有新的对话出现未读。静音的账号不弹通知，但未读数仍计入总数。WhatsApp 网页自带的通知被关掉了，因为它看不出是哪个号发来的。

不做的事：不往 WhatsApp 页面注入脚本，不伪装画布、显卡、音频等指纹。这些对 WhatsApp 作用很小，维护成本高，而且本身容易被识别为自动化工具。

## 省内存

每个账号的 WhatsApp 网页本身大约占 300 MB，这部分省不掉。WAswitch 在不漏消息的前提下做了这些：

- **后台降级**：没在看的账号设为后台页面，Chromium 会降低它的优先级、节流定时器、释放画面缓存。消息由服务器推送，照常接收。
- **自动回收**：WhatsApp 网页开久了内存会越涨越多。后台账号超过 800 MB、没有未读消息、并且在后台待了 5 分钟以上时，会自动在后台刷新一次（同一个号至少隔 30 分钟）。刷新只要几秒，期间的消息会从手机同步过来。可以在设置或托盘菜单里关掉，阈值可选 600 / 800 / 1000 / 1500 MB。
- **省内存模式**：在设置或托盘菜单里打开后关闭显卡加速，整体再省一些内存，代价是动画没那么顺滑。重启后生效。
- **清理缓存**：设置 › 内存 › 清理缓存，清掉网页版账号可以重新下载的缓存（HTTP 缓存、显卡和代码缓存），释放磁盘空间。不清 cookie、IndexedDB、localStorage、Cache Storage，所以不会退出登录，聊天记录也还在；部分已下载的图片可能需要重新加载。轻量模式账号不受影响。
- **内存统计**：托盘菜单显示每个账号占用多少内存，托盘提示里显示总占用。这是近似值（只算每个账号的主页面进程），会比实际略低。

设置保存在用户数据目录的 `settings.json`。

## 自检

设置 › 隔离自检：逐个测试每个账号的代理出口，提示走真实 IP 的号、共用同一个代理端口或出口 IP 的号、时区和出口对不上的号。

开发时还可以运行离线自检脚本（不需要联网和 WhatsApp 账号，检查时区、语言、代理、代理断开时不直连）：

```bash
npx electron scripts/check-isolation.js
```

## MCP 接口（可选，默认关闭）

开启后，本机的 AI 客户端（Claude Desktop、Claude Code 等）可以通过 [MCP](https://modelcontextprotocol.io) 管理 WAswitch 里的账号。

开启方法：托盘图标右键 →“MCP 接口设置…”→ 勾选“开启 MCP 接口”。设置窗口会生成 Claude Code 的添加命令和 Claude Desktop 的配置，复制即可。

当前开放的工具（一层：账号管理，不读取聊天内容）：

| 工具 | 作用 |
| --- | --- |
| `list_accounts` | 列出账号：名称、是否当前显示、未读对话数、是否静音、页面状态 |
| `get_unread_counts` | 各账号未读对话数和总数 |
| `get_connection_status` | 各账号页面状态和错误说明（例如代理连不上） |
| `switch_account` | 切换到某个账号并显示窗口 |
| `add_account` | 打开“添加账号”窗口并预填名称和地区。不会直接创建：你确认代理并保存后才联网，扫码仍由你在手机上完成 |
| `rename_account` | 修改账号显示名称 |
| `remove_account` | 删除账号；软件会弹窗让你确认，2 分钟没人确认视为取消；同一时间只会有一个确认框 |

第二层：读对话列表（默认关闭，在“MCP 接口设置”里单独打开）

| 工具 | 作用 |
| --- | --- |
| `list_chats` | 读某个账号左侧对话列表里已经显示的对话：名称、未读数、时间、置顶、静音、是否群组 |

- 只读：在隔离环境里读页面文字，不点开对话、不滚动、不标已读、不改页面。只能读到列表顶部已经显示的对话（通常 15 到 25 个），归档的对话不在里面。
- 每次读取都会弹窗确认：拒绝 / 允许这一次 / 10 分钟内允许。“10 分钟内允许”只对这一个连接、这一个账号有效，可以在设置里随时撤销；打开预览、账号掉线、关闭第二层或重启软件都会清掉。2 分钟不选视为拒绝。同一账号每 5 秒最多读一次。
- 最后一条消息预览另有开关，默认关闭。
- 读到的内容会发给你用的 AI 服务商，但不会保存到电脑上。设置窗口只记录谁、什么时候、读了哪个号、几个对话（只在内存里）。
- 对话名称和预览是聊天对方写的文字，工具说明里提醒了 AI 这些只是数据，不是指令。

读完整聊天记录需要点开对话，会标为已读，暂不提供。发消息、群发属于后续版本，会默认关闭、单独开关，并且每次发送都要在软件里确认。

安全措施：

- 只监听 `127.0.0.1`，只接受本机连接；`Host` 头只接受 `127.0.0.1` 或 `localhost`，防止 DNS 重绑定。
- 浏览器网页发起的请求（带 `Origin` 头）一律拒绝。
- 每个请求都要带随机 token。token 和端口保存在软件数据目录下的 `mcp-token.json`，只有本人可读（0600）。关闭 MCP 时删除这个文件，重新开启或点“断开全部并更换 token”时换新 token。
- 设置窗口里的 token 是打码显示的，点“复制命令”才会复制真实 token。注意 Claude Code 会把 token 保存在它自己的配置文件里；换 token 后要用新命令重新添加。
- Windows 上 0600 权限不起作用，token 文件靠用户目录本身的权限保护（其他 Windows 用户读不到）。
- 设置窗口显示当前已连接的客户端和调用次数。
- 关闭时不加载任何 MCP 代码，不占内存。

Claude Desktop 只支持 stdio，所以通过 `bin/waswitch-mcp.js` 桥接。它每次连接时从 `mcp-token.json` 读最新的 token，换 token 后不用改配置。

自检（不需要 Electron 和 WhatsApp 账号）：

```bash
npm run check:mcp
npm run check:wa-page   # 用模仿 WhatsApp 结构的测试页检查读取对话列表是否正确、是否只读（需要 Electron）
```

## 本地运行

需要 Node.js 20+。

```bash
npm ci
npm start
```

## 打包安装包

```bash
npm run dist
```

产物在 `dist/` 目录。

推送 `v` 开头的 tag（例如 `v0.2.0`）时，GitHub Actions 会自动打包 Windows 和 macOS 安装包并发布到 Releases（标为预发布）。
